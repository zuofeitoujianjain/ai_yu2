# aiyu 开发计划（任务分组 · 分批开发 · 统一测试）

> 依据 `docs/功能规划.md` 的功能清单整理。
> 原则：**依赖相近的功能放一批**（改动集中、减少来回改文件），**彼此独立的功能可并行**，
> 每批开发完做**批内自测**，全部完成后做**统一集成 + 回归测试**。
> 落地顺序建议按「阶段一 → 阶段五」推进。

---

## 分组总览

| 批次 | 功能 | 主题 | 难度 |
| --- | --- | --- | --- |
| **A 交互基础** | 关键词触发、限流冷却、指令系统 | 消息响应策略层 | 低 |
| **B 人格与记忆** | 多角色切换、多群独立人设、用户画像 | 上下文/人格组织 | 中 |
| **C AI 能力进阶** | 工具调用/Agent化、智能路由、图片理解 | DeepSeek 调用方式升级 | 中 |
| **D 长期记忆** | 向量记忆（chromadb/faiss） | 记忆模块 | 高 |
| **E 主动能力** | 定时推送、进群欢迎、群摘要 | 定时/事件触发 | 低 |
| **F 管理与可观测** | Web 面板、掉线告警、黑白名单 | 运营侧 | 高 |
| **G 工程化** | Docker 部署、热更新配置 | 部署层 | 中 |

---

## 阶段一：A 组 · 交互基础（**先做，收益最大**）

**改哪**：`bot.py` 的 `handle_event` / `handle_group` / `handle_private` 附近（响应决策层）。
**功能**：
1. **关键词触发**——首次 @ 启动对话后，后续命中关键词（如"鱼"）免 @ 自动回
2. **指令系统**——`/help`、`/人设 高冷`、`/开关 图片`、`/群设置` 等斜杠命令
3. **限流冷却**——防止刷屏/误触发（按人/按群频控）
**依赖**：无（最底层，可独立开工）。建议把"是否响应本次消息"抽成可插拔判定函数，为后续批次留接口。
**批内验收**：新增关键词/指令/冷却的自测用例；原 @触发、私聊行为不变。

## 阶段二：B 组 · 人格与记忆（依赖 A 的指令系统）

**改哪**：上下文构建 + 人设加载。
**功能**：
1. **多角色切换**——一个群多个 AI 人格（`/人设 xxx` 切换），**预留人格切换接口**
2. **多群独立人设**——不同群配不同角色/语气
3. **用户画像**——记住成员昵称、常用话题
**依赖**：A 组的 `/人设` 命令（B-1 用到）。
**批内验收**：一条消息在不同群/不同人设下取到正确 system_prompt；无 @/多角色冲突。

## 阶段三：C 组 · AI 能力进阶（最出彩，可放后）

**改哪**：`ask` / `chat_completion`（调用 DeepSeek 的方式）。
**功能**：
1. **工具调用 / Agent 化**——给模型开放 tool（联网搜索/翻译/天气），AI 自己决定调哪个
2. **智能路由**——简单问题走 v4-flash-low，复杂/推理题自动切 **v4-flash-high 思考模型**
3. **图片理解**——@它带图，用 **deepseek-v4-flash-vision-exp** 看图回答
**依赖**：无强依赖，可与 D/E 并行。
**批内验收**：tool 生效、路由命中、图片消息走 vision 模型且返回可发出去的回复。

## 阶段四：D / E 组（可并行）

**D 长期记忆**：接入向量库（chromadb/faiss），跨会话记住用户偏好/前因后果。
- 独立模块，`save / recall` 两个接口；与 B/C 通过上下文注入衔接。
- 批内验收：写入后能召回，不影响原短期记忆。

**E 主动能力**：定时推送、进群欢迎、群摘要/复盘。
- 改哪：新增定时任务入口（asyncio 调度）+ 群事件监听。
- 批内验收：到点触发、新人进群触发、每晚摘要生成。

## 阶段五：F / G 组（运营与工程）

**F 管理与可观测**：Web 管理面板、掉线/报错告警、权限与黑白名单。
- 独立 Web 服务读 `bot.py` 运行数据；告警复用发消息通道。
- 批内验收：面板可看日志/改人设/开关功能/统计；断线能收到通知；白名单生效。

**G 工程化**：Docker/一键部署、热更新配置。
- 批内验收：容器/脚本一键起；改 config 不重启即生效。

## ✅ 统一测试（全部开发完后执行）

> 每批已做**批内自测**，此阶段做**整体联调 + 回归**，确保"原功能不被破坏、新功能协同正常"。

### 1. 自动化回归
```bash
python bot.py --selftest
```
- 保留并扩展消息解析用例（CQ 码/数组/@全体/@他人/@后无文本）。
- 为每个新增功能补 1~2 条用例（关键词、指令、冷却、路由、记忆）。
- 建议引入 pytest，mock DeepSeek 响应，让测试不依赖真实 API/QQ。

### 2. 手动场景用例（一张清单逐条过）
| # | 场景 | 预期 |
| --- | --- | --- |
| 1 | 群里 `@邪恶鲸鱼娘 你好` | 正常回复 |
| 2 | 首次 @ 后再发含"鱼"内容（不 @） | 关键词触发回复 |
| 3 | `/人设 高冷` 后再次对话 | 人设切换生效 |
| 4 | 说"清空记忆" | 重置该会话 |
| 5 | 长回复 | 自动拆条 |
| 6 | 多群不同人设 | 各群各用各的 |
| 7 | 图片消息 | 走 vision 模型回答（或按配置） |
| 8 | 断网/掉线 | 自动重连并恢复 |
| 9 | 定时推送到点 | 触发发送 |
| 10 | Web 面板改人设 | 在线生效 |

### 3. 灰度上线
- 先在小号测试群跑 1~2 天（重点看触发频率、限流、报错），再拉到目标群。
- 回归重点：**原 @触发、私聊、记忆、拆分、重连** 必须和现在行为一致。

### 4. 通过标准
- `--selftest` / pytest 全绿；
- 手动清单 10 条全过；
- 原 5 项核心功能回归无差异；
- 灰度期无"深海信号不好"(API 报错) 或事件重复触发。

## 并行与协作建议

- **可并行**：A↔C、A↔D、D↔E、F↔G（互不强依赖）。
- **串行**：B 依赖 A（指令系统）；F 依赖 B/C 的数据接口。
- 若多人协作：一人一批；若单人：按阶段顺序推进，每批结束跑一次 `--selftest` 再进下一批。
- 每批完成即更新 `docs/功能规划.md` 的「✅ 已完成」表和本文件的批内验收勾选。
